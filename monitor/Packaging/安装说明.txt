Claude Watch {{PRODUCT_VERSION}} / build {{BUILD_NUMBER}}
===================

适用环境
--------
macOS {{MINIMUM_OS}} 或更高版本；本安装包架构：{{ARCHITECTURE}}。
本次仅提供 Apple Silicon（arm64）安装包；不包含 Intel 架构。
后台需要 Python 3.9 或更高版本；安装程序不会自动安装 Python。
本版本为本机临时签名（ad-hoc），未经过 Apple Developer ID 签名或公证。

安装监控界面
------------
1. 运行“安装或更新后台.command”：统一替换应用和后台，旧应用移入废纸篓，保留账号与保护设置。
2. 安装器只清理 Claude Watch 的旧辅助功能授权。从“应用程序”打开新版后，按 macOS 提示重新授权；不需要填写账号、节点或 IP 配置。
3. 卸载时运行“卸载应用.command”，会移除自有后台任务和应用、清理其辅助功能授权；账号资料与原版保镖保留。直接拖拽删除应用无法代替这一步权限清理。

界面日间使用白色卡片与浅色背景；只有已确认或存在路径差异的真实连接才会显示流动亮段，未确认路径保持静止。动画只表示连接样本，不表示传输速率。

本版功能
--------
2.9.5 统一环境、启动与账号、后台保护、概览和连接页的会话显示。Claude 正常关闭后显示“后台保护待命，无需操作”；异常锁定仍展示原因及受控恢复入口，读取失败不会冒充待命。几个页面读取最新同源状态，旧启动成功提示明确标为上次操作。后台异常拦截、IP/DNS/WebRTC 校验、账号和回滚机制不变。
2.9.4 按 TAG 实际 GLOBAL/规则模式核对完整代理链，直连、错误节点、缺失关联仍不通过。概览复用后台自动会话基准，区分当前、历史、待核对和已拦截；不再要求手工建立旧基线文件。安装替换等待旧后台完整退出，失败回滚应用；新版首次启动检查并请求辅助功能权限。
2.9.3 补齐连接采样状态和显示连续性：无新连接保留带原时间的静止历史路径，失败或过期计数显示 —；五类用途固定存在。换网络、换进程后旧路径仅归档，历史不参与启动校验和保镖判断。需要同步更新完整后台 2.8.3 才能取得采集回执。
2.9.2 修复 TAG 的 TUN/fake-IP 连接关联；核对同一内核的 DNS 映射、源连接、进程身份及时间，不省略目标校验。两产品共用已关联平台路径的动画规则，组件连接不会冒充平台请求。现有路径差异与保护判断保留。
包含 Claude、ChatGPT、Cloudflare 品牌 Logo 与本地国旗；支持 IP 评分、
DNS / WebRTC 独立检测页，以及按服务名称分组的平台、MCP 与组件连接。
国旗取自已有 IP 归属数据，未知时不猜测。Logo 与国旗均本地打包，
显示图标不会额外联网。独立诊断由手动触发，实时环境页打开即检测；超时或空结果不显示安全。

2.9 日常入口使用三个页面：
“环境状态”（⌘1）：自动识别代理与活动网络，运行 14 项实测检查。没有软件下拉框，
地区、日期、时区和网络服务使用本轮实测值；不需要填写国家、时区、出口 IP 或 DNS 名单。
未知或多个候选不会猜测通过。三个页面共用检测事实与会话保护状态。
“启动与账号”（⌘2）：单独检查启动要求并列出具体缺项。DNS 与 UDP/STUN 始终必检，未知或不匹配不放行。当前资料槽不可重复切换；
启动及切换仍独立通过原有校验，账号归档、版本确认与恢复机制保留。
“后台保护”（⌘3）：分别显示 Claude Watch 保镖、原版保镖、时区守护、自动更新的实际状态。
单项变更先预览具体值与权限，确认后执行并回读。原版保镖独立并行，本页不提供停用原版的按钮。
未配置本项目发布源与公钥时，自动更新显示尚不可用；不会在环境确认时注册无源任务。
14 项卡片保留悬停预览、点击固定、复制和 Esc 关闭；历史样本灰显。高级修改支持保存与撤销。
后台或环境变更失败按事务恢复，外部冲突保留供处理；恢复入口为“恢复未完成变更”。
地区/日期格式与时区按本轮出口核对，日本要求 ja_JP + Asia/Tokyo，英文语言独立保持。
同国家只作辅助信息，不能替代 DNS 可信参考、WebRTC 公网候选和代理路径校验。
WebRTC 检测仅覆盖当前 WebView；本工具未新增全系统包过滤，防漏仍依赖代理/TUN 的实际承接。
真实账号登录保持与钥匙串隔离仍未完成实机验收。

本版同步上游 macOS 增量：新增“独立代理诊断”，支持明确指定 HTTP/HTTPS/
SOCKS5/SOCKS5H 入口，只检查到 Claude 网页/API 的传输，不授予启动许可。
账号 A/B 直接复用固定版本原版源码，在私有暂存目录中执行归档和载入；
首次 A 保存当前资料，首次 B 先保存 A 后载入空 B。空槽只显示“未保存”。
完整哈希校验、启动门禁与失败恢复保留；新事务 schema 3，兼容旧 schema 1/2 恢复。
只读登录信息是独立详情，不作为切号前提，也不把本地存档当成远端认证结果。
有未完成的新切换事务时，应使用本版或更新版本恢复，不能降级到旧恢复器。

应用及后台更新
------------
界面版本为 {{PRODUCT_VERSION}}，附带后台脚本为 {{BACKEND_VERSION}}，两者版本分别管理。
新账号、独立诊断与保护功能需要完整的 {{BACKEND_VERSION}} 后台及运行组件。
本机已经安装同版本完整后台时，不需重复安装。
更新时统一运行“安装或更新后台.command”。挂载 DMG 不会自动安装或重置权限。

该命令会先检查 Python 3.9、应用签名、arm64 架构及运行组件校验值，再替换应用并更新
io.local.claudewatch.agent；确认后保留既有账号、日志、自动会话基准及保护配置。
它不会启动 Claude、Codex 或 ChatGPT，也不会修改 TAG 配置。

提醒行为
--------
自动监控默认仅向通知中心发送非阻塞提醒，不会反复弹出对话框打断工作。
普通的新网络端点仅写入本地日志。未授权进程、敏感目录描述符、代理链差异、
环境变化和服务候选属于警告：无声发送到通知中心，同一标题与类别至少间隔
300 秒。只有明确的监控或采样失效属于严重事件：后台会显示确认框，同类事件
至少间隔 600 秒；采样不会因此停止。手动执行 `test-alert` 时，仍保留用于
确认通知通道的测试弹窗。

新装且没有旧设置时，Claude Watch 的自动启动校验与会话保护默认开启；
已有的明确停用设置会保留，可在后台保护页启用，无需填写网络参数。
完整启动校验通过后自动记录本次会话的出口 IP。运行期间 IP 改变（即使同国）、
中国归属风险、DNS/WebRTC 风险或代理/TUN 确认失效都会停止 Claude。
连续两轮无法核验必要运行状态、或 DNS/WebRTC 有效证据超过 300 秒，也会停止。
失败会写明原因，不冒充中国出口或 IP 变化；历史数据不能续期放行。
停止状态会保留，刷新不会重建基准或自动重启 Claude。再次主动启动必须完整复检。
仅保护当前用户的 Claude Desktop，不自动退出 Codex/ChatGPT；有检测与退出延迟，不是防火墙。

升级
----
将新版 App 拖入“Applications”替换旧版。要升级后台采集逻辑，
再手动运行本卷中的“安装或更新后台.command”。

受控启动
--------
从 Dock 或普通终端直接启动 Claude、Codex、ChatGPT，不会登记受控授权会话。
Claude Watch 会停止没有有效受控会话的 Claude Desktop；请从“启动与账号”页的
“检查并启动 Claude”进入。普通启动无需初始化 A/B 账号槽，也无需手工配置 IP。
本节确认的受控保护入口是 Claude Watch 界面的“检查并启动 Claude”。
Codex/ChatGPT 的进程观察、连接显示和退出管理，不等于已有 Claude 的整套会话 IP 保护。
Rust 迁移候选的其他桌面/CLI 启动已接入统一服务，并通过替代进程隔离验证；
真实AI服务与完整窗口验收仍未完成，不作为当前已安装版的可用入口承诺。
这些入口不使用旧脚本、手工环境基线或旧预检，也不扩展 Claude 的自动退出保护。

卸载后台
----------
在终端运行已安装的脚本：

  "$HOME/Library/Application Support/ClaudeWatch/claude-watch.sh" uninstall

卸载保留既有日志和环境基线；删除界面 App 不会自动停止后台服务。
新增时区或自动更新任务由卸载流程分别停止。账号存档默认保留，删除账号库
需要另行明确选择；当前 Claude 活动资料目录不会被此清理删除。
