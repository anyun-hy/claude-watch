# 保护与账号设计

本文描述当前实现；版本摘要见 [CHANGELOG.md](../CHANGELOG.md)。旧版逐轮开发记录已移到忽略目录 `local/archive/`。

## 数据与判断

环境页与启动要求预览共享检测事实；启动操作仍独立执行完整的新鲜度、上下文和风险校验。当前值、历史值及来源分别展示，缓存不续期放行。

TAG 入口通过监听者路径、PID、启动身份和控制器覆盖核对。实际连接继续检查源地址／端口、协议、进程、连接时间与目标证据。TUN / fake-IP 的目标转换必须有同一内核的新鲜映射证明。

GLOBAL 模式核对 GLOBAL 的完整选择链；规则模式按实际命中规则及可独立解析的代理选择核对。显式保存的分组／节点要求继续生效，DIRECT、错误节点、缺失规则或关联证据不通过。

## 会话状态

| 状态 | 界面含义 | 行为 |
| --- | --- | --- |
| 保护运行中 | 当前会话与出口已核对 | 按原有策略继续检测 |
| 待命 | Claude 正常关闭，后台就绪 | 显示“后台保护待命，无需操作” |
| 启动中 | 正在绑定受控进程 | 自动更新结果 |
| 检测未完成 | 查询、身份或风险证据暂缺 | 显示原因，保留有界重试与失效处理 |
| 已锁定 | 命中停止条件 | 保留原因，恢复使用需受控启动 |
| 历史记录 | 结果过期或旧会话 | 不表示当前安全，不授予启动许可 |

`SessionProtectionEvidence` 选择最新只读回执，`SessionProtectionPresentation` 统一环境、账号、后台、概览和连接页的显示。它们不写会话文件、不改变后台门禁。锁定状态优先，过期或失效的后台不会被显示为正常待命。

## 受控启动与运行保护

`watch-engine launch` 与 `watch-sandbox-launcher` 先执行完整预检，Rust 运行时的受控会话层核对启动时实测出口与风险回执，随后通过 Seatbelt 沙箱与内核令牌绑定进程身份。启动失败保持回滚与异常记录。

会话 IP 基准不会随自动刷新改变。运行中 IP 改变（包括同国）、CN 出口、DNS / WebRTC 风险、必要身份连续无法核验或证据过期时，后台按既有规则请求退出 Claude。

停止记录不会由刷新自动清除；新的受控启动通过完整校验后建立新会话。此为进程级保护，存在采样窗口，不是防火墙。

## 账号 A/B

固定版本上游来源记录在 [UPSTREAM.json](ThirdParty/ClaudeSwitcher/UPSTREAM.json)。原版账号函数经来源校验后承担资料归档与载入；主项目负责受控进程、完整校验、事务发布和失败恢复。

首次使用 A 保存当前资料。切换时先保存当前槽，再载入目标槽；未保存的 B 是空资料槽。当前登录识别通过 Claude 账号界面读取，与 A/B 存档状态分开，不把存在本地文件等同于登录成功。

## 升级与权限

原生安装器（`crates/watch-installer` 与 `watch-engine install`）验证应用标识、签名、arm64 架构和组件哈希，等待旧后台退出后替换。旧应用移入废纸篓，失败恢复旧应用；不删除 Claude 资料、账号 A/B 或代理配置。

安装和卸载只清理 `io.local.watchpanel` 的 Accessibility 记录。新版首次打开请求系统授权；授权后自动重新读取登录状态。不会清理其他应用权限或编辑 TCC 数据库。签名更新器同样使用限定到本工具的权限清理。

无本项目发布清单和公钥时，自动更新不可用。完整更新验证与恢复逻辑位于 `crates/watch-engine`（`watch-engine update`）。

## 维护边界

- 后台与界面版本分别管理，版本默认值分别在 Cargo 清单及 `build.sh` / `package-dmg.sh` 中。
- 原版保镖独立运行；正常应用升级保留两套服务及用户环境设置。
- 实机验收记录留在忽略目录 `reports/`；当前记录为 `build297-install.json`。
- 构建、模拟测试、实机验收、安装和 Git 发布分别记录，不相互代替。
